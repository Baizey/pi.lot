# Herdr pane status

In [Herdr](https://herdr.dev/), pi.lot’s Herdr extension reports `working`, `idle` (including completed runs), and `blocked` for the interactive root Pi session. It reports automatically when Herdr supplies `HERDR_ENV=1`, `HERDR_PANE_ID` and a local `HERDR_SOCKET_PATH`. Other Pi modes and subagent sessions do not report independently. A missing, invalid or unresponsive socket does not block Pi.

**A separate Pi resource.** pi.lot ships both `src/pilot-extension.ts` (Pilot) and `src/herdr/herdr-extension.ts` (Herdr), enabled by default. In `pi config`, find `herdr/herdr-extension.ts` in the pi.lot package’s Extensions list. You can disable either extension independently. With only Herdr enabled, root lifecycle and manual compaction still report normally, but there are no Pilot policy or sign-in waits. With only Pilot enabled, there is no pi.lot Herdr reporting.

If you already filter the package’s `extensions`, Pi 1.6 does not treat an exact `+src/pilot-extension.ts` by itself as an allowlist. Herdr stays enabled by default with that setting. A plain positive pattern matching only Pilot, an empty array, or an exclusion can leave the Herdr entry disabled. If you want Herdr, enable its discovered entry in `pi config`; otherwise keep the existing filters or disable it there. To keep only Herdr enabled, explicitly disable Pilot as well. pi.lot does not change your settings.

**Use only one reporter.** If you already load the reporter installed by `herdr integration install pi` (typically `~/.pi/agent/extensions/herdr-agent-state.ts`, or under `PI_CODING_AGENT_DIR`), disable pi.lot’s Herdr entry or launch with `PILOT_HERDR_REPORTING=0`. To use pi.lot’s Herdr reporting, do not load the upstream reporter in that Pi process. pi.lot does not scan for, modify, or uninstall extensions. It does not consume the upstream adapter’s `herdr:blocked` event.

Policy approvals awaiting a human at the root terminal take priority, including approvals requested by a child. Automatic reviews and background child work do not set root-pane status. `/server login` also reports a wait while it asks for credentials. General settings, custom loading screens and dialogs outside these Pilot-owned flows are not reported through Herdr IPC. Manual compaction counts as work. Pi settles a run only after retries and automatic continuations finish. Pi’s own terminal status output remains active alongside this integration.

Reports go only to the inherited local Herdr socket. They contain the pane ID, lifecycle status, a fixed generic label for a wait, and Pi’s native absolute session path (or session ID if no path is available), matching Herdr’s Pi identity fields. Pilot does not send dialog titles, request or conversation content, credentials, tool arguments, or resume commands. Herdr uses its own Pi resume behavior and releases the pane on process exit; Pilot cancels pending reports when the Pi session shuts down or is replaced without erasing the resume reference.

Wire behavior is based on Herdr [v0.9.5’s Pi adapter](https://github.com/herdrdev/herdr/blob/v0.9.5/src/integration/assets/pi/herdr-agent-state.ts) (integration version 9, source `herdr:pi`) and its [process-owned release contract](https://github.com/herdrdev/herdr/blob/v0.9.5/src/integration/tests.rs). Herdr is [Apache-2.0 licensed](https://github.com/herdrdev/herdr/blob/v0.9.5/LICENSE). Pilot implements the protocol in `src/herdr/` without bundling the upstream extension.
